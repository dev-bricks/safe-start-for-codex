2. TARGET PERSONAS & USER JOURNEYS
================================================================================
1. Windows Codex Desktop Power Users & Prompt Engineers
   - Needs: Run multiple recurring local automations (morning digests, repository synchronizations, news aggregators) without freezing Windows or exceeding rate limits every time their workstation boots or wakes up from sleep.
   - Pain Points: When Codex Desktop launches, all automations scheduled during downtime fire simultaneously, maxing out CPU cores, hammering OpenAI API quotas, and locking up the Electron/Win32 UI.
   - Safe Start Solution: Automatically pauses active automations before boot, takes an atomic backup snapshot, launches Codex cleanly, immediately releases an urgent lead batch whose schedules lie safely ahead, and releases the remainder gradually in configurable intervals.

2. Autonomous Multi-Agent Swarm Operators (Claude Code, Codex CLI, Gemini Antigravity, Kimi)
   - Needs: Orchestrate multi-agent local workflows where autonomous agents schedule background tasks without colliding or creating unbounded background process leaks.
   - Pain Points: Orphaned background `codex.exe` instances linger silently in the Windows process table, holding file locks on SQLite state databases and preventing scheduled routines from executing.
   - Safe Start Solution: Built-in process family supervisor identifies stale zombie processes beyond idle thresholds while carefully preserving active UI sessions. Machine-readable context in `llms.txt` enables local LLMs to invoke and inspect gating status natively.

3. DevOps & System Reliability Engineers (SREs)
   - Needs: Maintain deterministic, auditable startup policies across developer machines, CI runners, and dedicated build workstations.
   - Pain Points: Manual edits to automation TOML files risk corrupting syntax or leaving automations permanently disabled after unexpected crashes.
   - Safe Start Solution: Atomic TOML serialization via staging files, automatic snapshot backups before any file modification, and a dedicated `restore-latest` emergency recovery command.

4. Enterprise Security & Compliance Auditors
   - Needs: Ensure local automation tooling adheres to strict zero-egress, unprivileged user mode, and permissive licensing constraints.
   - Pain Points: Untrusted third-party desktop tools often bundle telemetry, request administrative/UAC escalation, or introduce restrictive copyleft dependencies.
   - Safe Start Solution: 100% Local-First / Zero-Egress (INV-LOCAL-01), strictly unprivileged execution without UAC (INV-SEC-02), zero external runtime dependencies, 100% permissive open-source license audit (THIRD_PARTY_LICENSES.md), and codified 48-hour security response SLA (INV-SLA-10).

5. GOVERNANCE & RUNTIME INVARIANTS
================================================================================
- INV-LOCAL-01: 100% Local-First & Zero Egress (no network calls, zero telemetry, zero remote tracking).
- INV-SEC-02: Non-Elevation / RunAsInvoker (runs strictly in standard user mode without UAC elevation).
- INV-FILE-03: Snapshot-Before-Mutation (creates timestamped backups prior to modifying any configuration).
- INV-RESTORE-04: Selective Restoration Guard (only re-enables automations paused in current session).
- INV-CATCH-05: Conservative Catch-Up Policy (strictly read-only analysis; never triggers forced runs).
- INV-PROC-06: Targeted Process Supervision (restricts termination to ChatGPT.exe/codex.exe beyond age limits).
- INV-INTEG-07: Atomic TOML Serialization (staging files and atomic renames prevent partial writes).
- INV-FAIL-08: Fail-Closed Diagnostics (halts on invalid configurations without modifying active files).
- INV-PLAT-09: Cross-Platform Operating Parity (Windows production execution with Linux/macOS smoke tests).
- INV-SLA-10: Dual Security Response & Triage SLA (48-hour acknowledgment, 5-business-day triage).
